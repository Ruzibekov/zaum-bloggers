# ZAUM · Блогеры

Рабочий экран менеджера по рекламе у блогеров. Сервис собран поверх демо-таблицы «Демо блогеры» и отвечает на вопросы, с которыми его открывают каждое утро:

- что выходит сегодня и до конца недели;
- на каком этапе каждое размещение;
- кому и что нужно сделать прямо сейчас;
- сколько стоит реклама вместе с товаром и какой получается CPM.

Все блогеры и цифры вымышлены, это отмечено в интерфейсе плашкой «Демо-данные».

## Что на экране

**Заголовок дня.** Сегодняшняя дата, сколько публикаций сегодня и до конца недели, сколько размещений ждут действия.

**«Где сейчас реклама».** Это воронка из четырёх статусов таблицы: Согласование → Запланировано → Опубликовано → Результаты получены. В каждом этапе показаны количество, сумма и полоска, где один штрих равен одному размещению. Штрих с обводкой — размещение, которое требует внимания. Клик по этапу фильтрует список.

**«Ближайшие 7 дней».** Публикации по дням. Если до даты осталось меньше недели, а размещение ещё на согласовании, рядом стоит пометка «Ещё не согласовано».

**«Нужно сделать».** Задачи берутся из двух источников:

1. колонка «Комментарий» («Нужна дата публикации», «Проверить результаты»). Комментарии-заметки вроде «Демонстрационные данные» задачами не считаются;
2. сверка статуса с датой рекламы. Если дата прошла, а размещение всё ещё на согласовании или запланировано, это «Дата прошла, а реклама не вышла». Если статус уже «Опубликовано» или «Результаты получены», а дата ещё не наступила, это отдельная группа «Проверить данные в таблице».

Кнопка «Все N» открывает список, отфильтрованный по этой задаче.

**«Затраты по таблице».** Сюда входят стоимость размещений и себестоимость товара, деление на платные и бартерные размещения, суммарный охват сторис и просмотры рилс, средний CPM. Если CPM удалось посчитать не для всех строк, рядом написано «предварительно: по N из M».

**«Все размещения».** Список или календарь месяца. Поиск работает по блогеру, артикулу, комментарию, площадке и формату (горячая клавиша `/`). Есть фильтры по статусу, площадке, бюджету и формату. Сортировать можно кликом по заголовку колонки, а на телефоне через выпадающий список. Телефон показывает те же данные, что и десктоп, только в виде карточек.

**Карточка блогера** открывается по клику на любую строку и имеет свой адрес `#/b/<имя>`, им можно поделиться. В карточке собраны:

- этапы и дата;
- следующий шаг;
- деньги: размещение, товар и итог;
- CPM на шкале «Выгодно / Норма / Дорого» с медианой и разбросом;
- охваты и формат;
- ссылка на рекламу.

**«Сообщение блогеру».** Кнопка у задач в «Нужно сделать» и в карточке рядом со следующим шагом открывает готовый текст под ситуацию: спросить новую дату, если реклама не вышла, договориться о дате или подтвердить её, напомнить о публикации за 0–3 дня, запросить охват, просмотры и скриншот после выхода. Имя блогера, формат, площадка и дата подставляются из таблицы, текст можно поправить и скопировать одним нажатием.

Если блогера в таблице нет, карточка называется «Блогер не найден».

## Как считаются цифры

- **CPM** считается так же, как в таблице: стоимость размещения ÷ охват сторис × 1000, без себестоимости товара. Средний CPM равен суммарной стоимости, делённой на суммарный охват.
- **Оценка CPM** сравнивает CPM размещения с медианой по всем размещениям. «Норма» означает отклонение в пределах ±10%, «Выгодно» — на 10% и больше дешевле медианы, «Дорого» — на 10% и больше дороже. Для сравнения нужно хотя бы три размещения с CPM. Легенда есть под списком и на шкале в карточке.
- **Затраты** равны стоимости размещения плюс себестоимости товара. Бартерные строки в таблице тоже содержат стоимость размещения, и она учитывается как есть.
- Пустые ячейки не превращаются в ноль. В интерфейсе вместо них написано «нет данных» или «не указано».

## Источник данных

По умолчанию сервис читает Google Таблицу напрямую через CSV-выгрузку `gviz/tq?tqx=out:csv`. Google отдаёт её с CORS-заголовком, поэтому бэкенд не нужен. Сервис только читает таблицу и ничего в неё не записывает.

- Чтобы подключить свою копию, нажмите на источник в шапке и вставьте ссылку на таблицу. Таблица должна быть открыта по ссылке для чтения. Колонки ищутся по названию, поэтому их порядок не важен; обязательны только «Блогер» и «Статус».
- Если таблица недоступна (нет сети, закрыт доступ, неверная ссылка), сервис показывает снимок `public/data.json` и прямо пишет об этом над содержимым, с кнопкой «Повторить».
- Если вкладка была в фоне больше пяти минут, при возвращении данные обновляются, а старый экран остаётся на месте до прихода новых.
- Ссылку по умолчанию можно задать при сборке: `VITE_SHEET_URL=https://docs.google.com/spreadsheets/d/…`.

Снимок `public/data.json` лежит в репозитории, данные в нём вымышленные. Его можно пересобрать из выгрузки .xlsx:

```bash
python3 -I scripts/extract.py path/to/ZAUM_bloggers_demo.xlsx public/data.json
```

Скрипту нужен `openpyxl`. Он читает первый лист (или лист из `--sheet`), находит колонки по названию и сам пересчитывает CPM, не полагаясь на формулы. Тест проверяет, что CSV из Google Таблицы и `data.json` после скрипта дают одинаковые строки.

## Запуск

Нужен Node.js 20+.

```bash
npm install
npm run dev
```

Проверки и сборка:

```bash
npm run typecheck && npm run lint && npm test && npm run build
```

Готовая статика лежит в `dist/` вместе с `data.json`, её можно отдать любым статическим хостингом.

## Почему так

Таблица ведёт рабочий процесс, а не хранит архив: у каждой строки есть статус, дата и следующий шаг. Поэтому первый экран отвечает на вопрос «что делать сегодня», а аналитика по деньгам и CPM стоит ниже. Воронка этапов служит и сводкой, и фильтром. Задачи собираются из того, что менеджер уже пишет в таблицу, поэтому новых полей заводить не нужно. Таблица остаётся единственным источником правды, сервис её только читает.

Что улучшить дальше:

- колонки с фактическими результатами (охват и просмотры после публикации), чтобы считать фактический CPM рядом с плановым;
- напоминания о публикациях в Telegram;
- история изменений статусов.

## Стек

Vite, React 19, TypeScript, CSS Modules, Vitest. Структура по Feature-Sliced Design: `app → pages → widgets → features → entities → shared`. Шрифт Onest, светлая и тёмная темы по системной настройке, анимации отключаются при `prefers-reduced-motion`.
